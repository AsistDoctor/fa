# Техническая документация проекта

## 1. Общий обзор

Проект представляет собой веб-приложение для 3D-визуализации кампуса на базе Three.js.  
Система поддерживает загрузку моделей корпусов, работу с этажами, метками, dev-позиционирование, а также динамическое освещение по времени суток.

## 2. Структура проекта

- `index.html` — разметка UI и подключение модулей.
- `main.js` — основной runtime сцены и логика интерфейса.
- `styles.css` — оформление и адаптивные стили.
- `server.py` — dev-сервер, static hosting + dev API + SQLite.
- `model_positions.json` — fallback-конфиг позиций моделей.
- `labels.json` — пользовательские метки (если сохранены в файл).
- `docs/` — комплект документации для сопровождения и диплома.

## 3. Архитектура runtime

### 3.1 Сцена и рендер

- `THREE.Scene`
- `THREE.PerspectiveCamera`
- `THREE.WebGLRenderer`
- `CSS2DRenderer` для HTML-меток в 3D.

### 3.2 Загрузка моделей

Модели грузятся через `OBJLoader` из массива `modelFiles`.  
Используется батчевая/ленивая стратегия загрузки с прогрессом.

### 3.3 Система этажей

Реализованы:
- `currentFloor`, `buildingFloors`, `floorHeight`;
- переключение этажей `- / + / Все`;
- применение фильтра видимости по этажу для активного корпуса.

### 3.4 Система меток

- создание CSS2D-меток;
- редактирование параметров;
- привязка к модели;
- загрузка из `labels.json` и fallback из `localStorage`.

## 4. Хранение данных и реактивность (DEV)

### 4.1 Форматы и источники

- Основной fallback: `model_positions.json`.
- DEV persistence: SQLite (`dev_data.sqlite3`).

### 4.2 Серверный API (`server.py`)

- `GET /api/dev/status` — статус dev API.
- `GET /api/dev/model_positions` — все трансформы моделей.
- `PATCH /api/dev/models/{modelKey}/transform` — обновление одной модели.
- `POST|PATCH /api/dev/model_positions` — массовый upsert.
- `GET /api/dev/events` — SSE-стрим событий для realtime обновлений.

### 4.3 Клиентская синхронизация (`main.js`)

- При старте клиент проверяет API (`/api/dev/status`).
- Если API доступен, позиции читаются из БД.
- Если API недоступен, включается fallback на JSON.
- Изменения transform отправляются в API с debounce.
- Realtime-обновления между клиентами идут через `EventSource`.

## 5. Освещение и тени

### 5.1 Источники света

- `sunLightRef` (`DirectionalLight`) — основной дневной свет.
- `moonLightRef` (`DirectionalLight`) — ночной свет (без теней).
- `ambientLightRef` (`AmbientLight`) — фоновая подсветка.

### 5.2 Динамика времени

Функция `calculateSunMoonPosition()` рассчитывает положение и интенсивность света по локальному времени и сезону.  
`updateSunMoonPosition()` обновляет:
- позицию солнца/луны;
- интенсивность света;
- цвет фона (день/закат/ночь);
- визуальные сферы солнца и луны.

### 5.3 Стабилизация теней

Для устранения дневных артефактов:
- включен `PCFSoftShadowMap`;
- настроены `bias` и `normalBias`;
- увеличен охват shadow-camera солнца;
- цель солнца (`sunTargetRef`) фиксируется в центр сцены/пола;
- лунные тени отключены для стабильности и производительности.

## 6. Расширяемость

### 6.1 Переход на `GLB`

Рекомендуется перейти с `OBJ` на `GLB` для:
- меньшего размера ассетов;
- лучшей загрузки в вебе;
- более простого пайплайна материалов.

### 6.2 Этажные интерьерные модели

Планируется раздельная загрузка интерьеров по этажам:
- отдельный файл модели на этаж;
- lazy loading только активного этажа;
- хранение ссылок и трансформов в БД.

### 6.3 Production hardening

Перед релизом:
- отключить `DEV_MODE`;
- убрать dev-endpoints и UI позиционирования;
- оставить только read-only режим и пользовательские функции.

## 7. Запуск и проверка

```bash
python server.py
```

Проверка API:
- `GET http://localhost:3000/api/dev/status`
- `GET http://localhost:3000/api/dev/model_positions`

Проверка realtime:
1. Открыть проект в двух браузерах/устройствах по LAN.
2. Изменить позицию модели на одном клиенте.
3. Проверить применение изменений на втором клиенте.

## 8. Вывод

Текущая реализация покрывает ключевые задачи дипломного прототипа:
- 3D карта кампуса,
- управление этажами,
- dev-редактирование данных,
- реактивная синхронизация,
- динамическое освещение и рабочие тени.
